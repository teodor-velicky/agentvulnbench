## What the misses say

1. **Ranking, not detection, loses cases for the real tools.** Semgrep and Bandit each flag the key sink in 2 cases
   (agno, llama-index) at ranks 12 to 109: many look-alike sinks, no signal for which one an attacker reaches. The
   trivial reachability-aware rankbase lifts llama-index to rank 2 (the diagnostic column shows 0/21 for rankbase because it has no cached full list, so it is not comparable).
2. **The stub triage throws away surfaced true sinks.** PitSense's surface map holds the key sink in 4 of 21 cases
   but triage keeps one; with no LLM reasoning, G1 rejects. `untrusted-llm-input` is the largest group (9 cases) and
   PitSense scores 0/9 there, consistent with CHAINLAB's proposed G1 rule for model-mediated attackers.
3. **Most cases are invisible to pattern tools**: path traversal in the MCP filesystem/git servers, the langflow
   missing-auth route, the DNS-rebinding default, the SQL, token-passthrough and OAuth confused-deputy cases. There is
   no dangerous call at the sink line to match.
4. Semgrep's registry packs fire little on TypeScript agent code (1 finding on each langchainjs tree, 0 on the MCP
   servers and inspector).

## Class mapping(adapters never read the answer key)

- Semgrep / Bandit: the first CWE in the rule metadata mapped by `bench/tools/common.py:CWE_CLASS` (for example
  94/95 → code-injection, 78 → command-injection, 502 → unsafe-deserialization, 22 → path-traversal,
  918 → ssrf), else `other`. Bandit's B307 `eval` carries CWE-78, which maps to command-injection, in the same
  family as code-injection.
- PitSense (its adapter drives the private engine and is not published): engine sink class code-exec →
  code-injection, ssrf-url-fetch → ssrf, template-ssti → template-injection, auth-bypass → authz-bypass,
  unsafe-deserialization and path-traversal unchanged. The one judgement call, `missing-origin-websocket` →
  dns-rebinding, matters for no case: the engine raised no candidate in the FastMCP server file.
- Ranking uses each tool's own signals only. Semgrep: severity, then confidence, then path and line. Bandit: the
  same order. PitSense: QUALIFIES, then DOWNGRADE (held for a human), each in surface-map order; REJECTs are dropped
  because the engine drops them. Sorting by path within a severity tier is arbitrary but deterministic and
  key-blind.

## Inputs, pins, caveats

- Source: the full repo tree at each case's vuln SHA, from the GitHub codeload tarball (no .git, no history, no
  advisory), per SPEC s2. URLs and tarball sha256 are in `bench/tools/src-manifest.json`. 0 members were skipped on
  extraction.
- Semgrep rule YAML is under the Semgrep Rules License, so it is not committed. Only its sha256 is
  (`SNAPSHOT.json`). The adapter refuses to run if the cached snapshot differs. p/typescript is byte-identical
  to p/javascript.
- Windows path limit: semgrep-core cannot open paths over 260 characters. On langflow and llama-index it failed
  with "Failed to obtain target files" (rc 2, 0 files scanned). Both were re-scanned from a short real-path copy
  (`--src-root C:/avb`). The adapter now treats rc 2 or 0 scanned files as an error, so a failed scan can never
  count as a real zero. Semgrep is 0/21 regardless; per-case scan-error and scanned-path lists were not committed.
- Semgrep scan errors (parse or timeout, recorded per case in `note`): 4 on each langchainjs tree (TypeScript
  `export type` partial parses in other files), 6 on langflow, 1 on bentoml-hvj5. Per-case error causes and file lists were not committed.
- CodeQL was not scored. Its licence allows academic research and analysis of open-source code, but it is unclear
  whether a company may publish benchmark scores with it. It was skipped while that is unclear.
- Not like-for-like with SPEC's "same budget cap for every tool": no cap was set, because every tool finished
  in minutes and was free.

Semgrep target counts (no silent 0-target scan): `bench/scores/v0/semgrep.targets.json` records scanned files per
case, all > 0 (minimum 72, mcp-filesystem-ghsa-hc55). 7 cases were added since the 14-case run; these 5
(langgraph, litellm, mcp-python-sdk-qx49, mcp-server-git-6hqx, vllm) were scanned from short-path copies (`C:/avb/<case>`); litellm had 75
parse/timeout scan errors. `src-manifest.json` covers all 21 trees.

## Reproduce

```
python -I bench/tools/fetch_src.py                                   # 21 trees -> bench/tools/.cache/src/ (gitignored)
# PitSense rows: produced by the private engine @ 5ae65df; its attempt files are committed and re-score below
python bench/tools/semgrep/adapter.py --jobs 2                       # Windows: --src-root C:/avb after copying trees to short paths
uv venv bench/tools/.cache/venv-bandit --python 3.12
uv pip install --python bench/tools/.cache/venv-bandit/Scripts/python.exe bandit==1.9.4
python bench/tools/bandit/adapter.py                                 # run with all cases (--cases without merge overwrites the file)
python bench/tools/rankbase/adapter.py
for t in pitsense semgrep bandit rankbase pitsense-surface; do
  python -I bench/scorer.py score bench/scores/v0/$t.attempt.json --no-docker --out bench/scores/v0/$t.json
done
python -I bench/tools/diag_anyrank.py && python -I bench/tools/tables.py
```

Scoring from the committed attempt files needs no network or Docker. Registry packs change over time, so a
fresh `--refresh-rules` download is a different tool configuration.
